# Phase 8 — UI Design Contract

> Visual and interaction contract for Discord embed output. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> 
> **Note:** This project is a Discord bot (Python). The "UI" is Discord embeds, slash command parameters, and ephemeral text responses. There is no web frontend, no CSS, no component library. All visual contracts below are expressed in Discord embed terms.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | discord.py embeds + app_commands |
| Icon library | Unicode emoji (inline) |
| Font | Discord system font (not configurable) |

---

## Spacing Scale

Discord embeds do not support custom spacing. Spacing is controlled by Discord's embed renderer. The following conventions apply within embed content:

| Token | Mechanism | Usage |
|-------|-----------|-------|
| Field separation | `inline=False` on all fields | Each player on its own line block |
| Section break | Empty-value section header field | Visual gap between "Transfers Out" and "Transfer Targets" |
| Inline separator | ` \| ` (pipe with spaces) | Between position and school within a field value |
| Line break | `\n` in field value | Between player details line and "Added" timestamp line |

Exceptions: none

---

## Typography

Discord embeds use Discord's system font at Discord-controlled sizes. The following semantic roles map to Discord embed formatting:

| Role | Discord Mechanism | Format |
|------|-------------------|--------|
| Embed title | `Embed(title=...)` | Bold, larger text (Discord-rendered). Max 256 chars. |
| Section header | `add_field(name=..., inline=False)` | Bold field name with emoji prefix. |
| Player name | `add_field(name=..., inline=False)` | Bold field name. Format: `{name} {star_emojis}` truncated to 256 chars. |
| Player details | `add_field(value=..., inline=False)` | Normal weight field value. Format: `{position} \| {school}\nAdded {relative_time}` |
| Footer | `set_footer(text=...)` | Small, muted text. Format: `Last updated: {datetime}` |
| Empty state | `Embed(description=...)` | Normal text in embed body. |

## Copywriting Contract

### Slash Command Descriptions

| Command | Description |
|---------|-------------|
| `/transfer-add` | Add a player to the transfer list |
| `/transfer-remove` | Remove a player from the transfer list |
| `/transfer-list` | View the transfer list for this channel's sport |

### Parameter Descriptions

| Parameter | Description |
|-----------|-------------|
| `type` | Transfer type: outgoing (leaving KU) or target (coming to KU) |
| `position` (on `/transfer-list`) | Filter by position (e.g., QB, WR, PG) |
| `name` | Player name |
| `school` | Previous/current school |
| `stars` | Star rating (0 for unrated, 1-5) |

### Choice Labels

| Value | Display Label |
|-------|---------------|
| `outgoing` | Outgoing (leaving KU) |
| `target` | Target (coming to KU) |

### Embed Titles

| Context | Title Format |
|---------|--------------|
| Transfer list (football) | {football_emoji} KU Football Transfer List |
| Transfer list (basketball) | {basketball_emoji} KU Basketball Transfer List |
| Continuation embed | {title} (cont.) |

### Section Headers (within grouped embeds)

| Type | Header Format |
|------|---------------|
| Outgoing | {door_emoji} Transfers Out |
| Targets | {target_emoji} Transfer Targets |

Section header field value format: `*{count} player(s)*` (italic, showing count)

### Emoji Reference

| Emoji | Unicode | Usage |
|-------|---------|-------|
| Door | `\U0001f6aa` | "Transfers Out" section header |
| Target | `\U0001f3af` | "Transfer Targets" section header |
| Football | `\U0001f3c8` | Football embed title prefix |
| Basketball | `\U0001f3c0` | Basketball embed title prefix |
| Star | `\u2b50` | Star rating display (repeated N times) |

### Player Field Format

| Part | Format | Example |
|------|--------|---------|
| Field name | `{name} {stars_or_empty}` | `John Smith ⭐⭐⭐⭐` |
| Field name (unrated) | `{name} Unrated` | `John Smith Unrated` |
| Field value line 1 | `{position} \| {school}` | `QB \| Alabama` |
| Field value line 2 | `Added {relative_time}` | `Added 3 days ago` |

### Success Confirmations (ephemeral text, not embeds)

| Action | Copy |
|--------|------|
| Add (with stars) | Added **{name}** ({position}, {school}) {star_emojis} to the {sport} transfer list. |
| Add (no stars) | Added **{name}** ({position}, {school}) to the {sport} transfer list. |
| Remove | Removed **{name}** from the {sport} transfer list. |

### Empty State

| Element | Copy |
|---------|------|
| Empty list embed description | No players on the {sport} transfer list yet. |
| Empty section | Section header omitted entirely (do not show "Transfers Out" if zero outgoing players) |
| Empty after position filter | No {position} players on the {sport} transfer list. |

### Error States (ephemeral text, not embeds)

| Error | Copy |
|-------|------|
| Duplicate add | **{name}** is already on the {sport} transfer list. |
| Not found (no suggestions) | **{name}** not found on the {sport} transfer list. |
| Not found (with suggestions) | **{name}** not found. Did you mean: {comma_separated_names}? |
| Wrong channel | This command can only be used in a football or basketball channel. |
| No permission | You don't have permission to manage the transfer list. |
| Generic error | Something went wrong. Please try again later. |

### Destructive Actions

| Action | Mechanism | Confirmation |
|--------|-----------|--------------|
| `/transfer-remove` | Immediate removal, no confirmation prompt | None -- consistent with Phase 7 `/recruit-remove` pattern. Editors are trusted users. |

## Pagination Contract

| Property | Value | Source |
|----------|-------|--------|
| Players per page | 10 | D-10 |
| Pagination mechanism | Multiple embeds in one response | D-11, D-12 |
| Section headers count toward page limit | No -- headers are "free" | RESEARCH.md Pitfall 3 |
| Max fields per embed (hard Discord limit) | 25 | Discord API |
| Continuation title format | `{original_title} (cont.)` | Existing Phase 7 pattern |
| Footer placement | Last embed only | Existing Phase 7 pattern |
| Max embeds per message | 10 (Discord limit) | Discord API |
| Overflow handling | `interaction.followup.send()` for embeds 11+ | Existing Phase 7 pattern |

### Display Order

1. Section header: "Transfers Out" (if any outgoing players exist)
2. Outgoing players sorted by position
3. Section header: "Transfer Targets" (if any target players exist)
4. Target players sorted by position
5. Footer with timestamp on final embed

## Interaction Contract

### Response Behavior

| Command | Response Type | Visible To |
|---------|--------------|------------|
| `/transfer-add` | Ephemeral text | Command user only |
| `/transfer-remove` | Ephemeral text | Command user only |
| `/transfer-list` | Ephemeral embeds | Command user only |

### Parameter Defaults

| Parameter | Default | Rationale |
|-----------|---------|-----------|
| `type` on `/transfer-add` | `"target"` if omitted | Most common use case is adding players KU is pursuing (D-02) |
| `position` on `/transfer-list` | `None` (show all) | Unfiltered is the default view (PORTAL-02) |
| `stars` | `0` (unrated) | Existing Phase 7 default |

### Position Filter Behavior

| Input | Matching | Example |
|-------|----------|---------|
| Case insensitive | `"qb"` matches stored `"QB"` | RESEARCH.md Pitfall 5 |
| Exact position match | No fuzzy matching on position | `"Q"` does NOT match `"QB"` |
